TENEBRA Roadmap

A practical release plan for operating the live network reliably and making future releases reproducible.

Current status: Mainnet is reported live by the operator. The public wallet calculates a 1% transaction fee automatically from the transfer amount.

Phase 1: Mainnet Stabilization

  • Run live health checks from an independent machine.
  • Confirm seed reachability, peer connectivity, block propagation and transaction confirmation.
  • Verify transactions from more than one public observer.
  • Record chain height, tip, peer count, confirmation latency and errors.
  • Test restore from backup on a clean host.

Exit criteria: Two independent observers agree on chain state; a test transfer confirms; restore and rollback procedures are documented.

Phase 2: Security and Dependency Hardening

  • Review the unmaintained clear_on_drop 0.2.5 dependency chain.
  • Run formatting, tests, Clippy and security checks in CI.
  • Review cryptographic dependency upgrades before deployment.
  • Add dependency pinning, checksum review and reproducible builds.
  • Test production key rotation and recovery.

Exit criteria: Security checks pass in a clean environment and recovery procedures are tested.

Phase 3: Wallet and Transfer UX

  • Verify recipient QR scanning on desktop and mobile.
  • Verify the 1% fee calculation: 10 TNB → 0.1 TNB; 20 → 0.2 TNB; 30 → 0.3 TNB.
  • Verify logout, automatic reconnection and encrypted local storage.
  • Test pending, confirmed and failed transfer states.
  • Keep private seed and password material local to the wallet.

Exit criteria: Wallet behavior matches the published fee policy and transfer status is clear from signing to confirmation.

Phase 4: DEX, NFT Marketplace and Scan

  • DEX: verify market data, balances, quote freshness and live transaction status.
  • DEX: define supported swap and listing flows, including unavailable-market states.
  • NFT Marketplace: verify collections, metadata, ownership and purchase/listing flows.
  • NFT Marketplace: validate rejected, pending and confirmed transaction states.
  • Scan: verify blocks, transactions, addresses and search results against the public chain tip.
  • Add mobile checks, empty states and network-error states across all three surfaces.

Exit criteria: DEX, NFT Marketplace and Scan show consistent chain data and never present stale data as confirmed.

Phase 5: Operations and Observability

  • Maintain uptime, peer, block, transaction and disk-space alerts.
  • Test chaos and concurrency checks in a controlled environment.
  • Verify log rotation, backup retention and alert delivery.
  • Publish an incident response runbook.

Exit criteria: Alerts are demonstrated and an operator can restore service from backup.

Phase 6: Independent Review and Release Governance

  • Freeze tagged release candidates with manifests.
  • Provide build, test, genesis, network and deployment evidence.
  • Track findings with owner, severity, evidence and verification.
  • Publish release notes separating verified facts, operator reports and open limitations.

Exit criteria: Reviewers can reproduce stated results and release decisions are documented.

Release cadence

Patch releases cover security and operational fixes. Minor releases add backward-compatible improvements. Major releases that change consensus, cryptography, network identity or transaction format require a migration plan, testnet rehearsal and explicit operator approval.
