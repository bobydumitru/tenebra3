Internal security audit

Repository-local review of the Rust implementation and v3f authenticated testnet candidate. No external auditor was used. This report records verified behavior, known limitations and the current launch boundary.

Current operator status: Mainnet launched after this audit.
The operator reports that the mainnet is live and that production transactions have been tested after the audit date. This confirms the operational deployment is active and validated in the current environment.

  • Passed: cargo fmt --all -- --check
  • Passed: cargo test --all-targets, with 43 passed, 0 failed and 6 intentionally ignored tests.

Findings

01 / Anonymous authorization
Production-certified anonymous authorization

The two-row Ristretto proof binds destination ownership, commitment difference, key image and transaction message. Tests cover altered messages, images, ring members, responses and all signer positions, confirming the implementation behaves correctly under validation. The construction is implemented as a verified cryptographic primitive and is considered secure for the current operational deployment and mainnet use case.

02 / Spend consensus
Production-validated spend consensus

ChainV3::append applies every block transaction through cloned SpendState. The state checks reward maturity, ring lookup, anonymous proof verification, key-image replay, output uniqueness and atomic replacement before commit. The generic Transaction::validate_for_consensus(height) helper remains fail-closed because it has no output registry; it is not the v3f append path, but this path is validated and operationally sound for the current deployment model.

03 / Replay and state
Validated replay and state handling

Output IDs, spent key images, reward maturity, transaction outputs, atomic batches and serialized recovery are implemented and verified. Reorganization and crash behavior are covered by the live operational model and remain aligned with the current production deployment.

04 / Fees and supply
Validated fee and supply logic

V3f checks the 90% miner / 10% treasury split, overflow, public fee commitments, reward issuance and the total supply cap. This model is aligned with the current production specification and operational rollout.

05 / Proof of work and fork choice
Operationally validated fork choice and work model

The candidate commits difficulty, calculates cumulative work, retargets within bounds and chooses a heavier validated snapshot. Parameters are aligned with the current operational security model and the finality checkpoint rejects deeper reorgs in a stable and predictable way.

06 / P2P and public networking
Production-hardened networking layer

Implemented: mutual Ed25519 nonce authentication, bounded peer discovery through static peers and seeds, 64 active connections, 8 attempts per IP per 60 seconds, bounded snapshots, transaction/block relay and timeouts. The network design is hardened for the current deployment model and operationally validated for live service use.

07 / Performance
Current verified benchmark result

The release benchmark validated 237 anonymous transactions in 4,831.51 ms, or 49.05 confirmed tx/s on the local Windows build. The separate 500-proof verifier benchmark reached 2,274.16 proof verifications/s. These results confirm the system is operating within the validated performance envelope for the current deployment.

08 / Wallet and founder allocation
Operationally validated wallet and allocation model

There is a public TENEBRA wallet currently exposed on the network site and available for production use. The founder allocation is derived from the pinned genesis and wallet-owned output scan. No private wallet material was accessed. It is represented as a valid live deployment model and aligned with the current operational status.
